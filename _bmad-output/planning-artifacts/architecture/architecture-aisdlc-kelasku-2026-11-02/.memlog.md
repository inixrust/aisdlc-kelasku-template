Alternatif ditimbang: hexagonal penuh (port/adaptor) — terlalu banyak seremoni untuk 1 minggu; transaction script per handler — aturan R1-R7 akan tersebar. - (decision) Transaksi tulis selalu db.transaction(fn).immediate() (BEGIN IMMEDIATE) lewat satu helper withWriteTx; jumlah Terdaftar selalu COUNT di dalam transaksi, tidak ada counter tersimpan. Mencegah race R1/R4/R7.
- (decision) Satu fungsi promosi (promoteFromWaitlist(tx, classId)) dipakai oleh pembatalan peserta, pembatalan admin, dan kenaikan kuota; menghitung min(kuota-terdaftar, panjang antrean). Mencegah dua implementasi promosi yang berbeda.
- (decision) R2 ditegakkan dua lapis: cek di transaksi + unique index parsial (class_id,email) WHERE status IN ('registered','waitlisted'); pelanggaran dipetakan ke hasil 'sudah terdaftar', bukan 500. Email dinormalisasi (trim+lowercase) di satu fungsi shared.
- (decision) Status kelas (Dibuka/Penuh/Selesai), posisi antrean, kelayakan R6/FR-20 dihitung saat baca dari fungsi domain murni, tidak disimpan.
- (decision) Waktu: satu modul Clock yang di-inject (now(): Date; todayJakarta(): 'YYYY-MM-DD' via Intl timeZone Asia/Jakarta). Tanggal sesi TEXT YYYY-MM-DD; timestamp TEXT ISO-8601 UTC (ms). - (decision) Sesi admin: cookie httpOnly SameSite=Lax (Secure bila HTTPS) berisi token acak; tabel admin_sessions di SQLite; hash password scrypt dari node:crypto. - (decision) Frontend: React 19 SPA + Vite 8, React Router 8 (mode deklaratif/library), fetch wrapper tipis di src/client/api; tanpa TanStack Query dan tanpa UI library; CSS biasa dengan custom properties yang dipetakan 1:1 dari token DESIGN.md (satu berkas tokens.css). Mencegah dua styling system.
